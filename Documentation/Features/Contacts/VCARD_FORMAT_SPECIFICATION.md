# vCard Format Specification

## Overview
This document defines the standardized vCard (.vcf) format used throughout the My CRM application for all drag and drop operations and contact data exchange.

## Standard Format
All vCard files generated by the application must conform to the following format specification:

### Example vCard
```
BEGIN:VCARD
VERSION:3.0
PRODID:-//Apple Inc.//macOS 15.6.1//EN
N:Soulier 🌟;Andrew;;;
FN:Andrew Soulier 🌟
ORG:Friend + Adventure Buddy;
TEL;type=CELL;type=VOICE;type=pref:(970) 988-2641
END:VCARD
```

## Field Specifications

### Required Fields
- `BEGIN:VCARD` - vCard start marker
- `VERSION:3.0` - vCard version specification
- `END:VCARD` - vCard end marker

### Standard Fields

#### PRODID (Product Identifier)
- **Format**: `PRODID:-//Apple Inc.//macOS 15.6.1//EN`
- **Purpose**: Identifies the software that generated the vCard
- **Required**: Yes
- **Value**: `-//Apple Inc.//macOS 15.6.1//EN`

#### N (Name)
- **Format**: `N:LastName;FirstName;MiddleName;Prefix;Suffix`
- **Purpose**: Structured name representation
- **Example**: `N:Soulier 🌟;Andrew;;;`
- **Notes**: Supports emojis and special characters

#### FN (Formatted Name)
- **Format**: `FN:DisplayName`
- **Purpose**: Full formatted name for display
- **Example**: `FN:Andrew Soulier 🌟`
- **Notes**: Should match the display name used in the application

#### ORG (Organization)
- **Format**: `ORG:OrganizationName;`
- **Purpose**: Organization or business affiliation
- **Example**: `ORG:Friend + Adventure Buddy;`
- **Notes**: Semicolon at the end is required for proper formatting

#### TEL (Telephone)
- **Format**: `TEL;type=CELL;type=VOICE;type=pref:PhoneNumber`
- **Purpose**: Phone number with type specifications
- **Example**: `TEL;type=CELL;type=VOICE;type=pref:(970) 988-2641`
- **Types**: 
  - `type=CELL` - Mobile phone
  - `type=VOICE` - Voice capable
  - `type=pref` - Preferred number

### Optional Fields

#### EMAIL
- **Format**: `EMAIL:EmailAddress`
- **Purpose**: Email address
- **Example**: `EMAIL:andrew@example.com`

#### ADR (Address)
- **Format**: `ADR:;;StreetAddress;City;State;PostalCode;Country`
- **Purpose**: Physical address
- **Example**: `ADR:;;123 Main St;Denver;CO;80202;USA`

#### NOTE
- **Format**: `NOTE:NoteText`
- **Purpose**: Additional notes about the contact
- **Example**: `NOTE:Met at conference 2024`

## Implementation Details

### Contact.toVCardString()
The primary method for generating vCard format in the application:
- Located in: `Core/Models/Contact.swift`
- Generates standardized vCard format matching this specification
- Handles all required and optional fields based on contact data

### Contact.fromVCardString()
The primary method for parsing vCard format:
- Located in: `Core/Models/Contact.swift`
- Parses vCard strings and creates Contact objects
- Handles both old and new format variations for backward compatibility

### Drag and Drop Integration
- All drag and drop operations use this standardized vCard format
- External drag operations (to other applications) generate .vcf files
- Internal drag operations can use both vCard and internal JSON formats
- ProviderBridge.swift ensures consistent vCard generation

## File Naming Convention
- **Format**: `ContactName.vcf`
- **Example**: `Andrew Soulier.vcf`
- **Sanitization**: Forward slashes (/) and backslashes (\) are replaced with underscores for file system compatibility. Spaces are preserved.
- **Fallback**: If name is empty, use phone number as filename

## Compatibility
- **Apple Contacts**: Fully compatible with macOS Contacts app
- **Other Applications**: Standard vCard 3.0 format ensures broad compatibility
- **Internal Use**: Optimized for My CRM's contact management system

## Error Handling
- Invalid vCard data is logged with detailed error information
- Fallback mechanisms ensure graceful handling of malformed data
- Empty or missing required fields are handled appropriately

## Testing
- All vCard operations are logged for debugging purposes
- Format validation ensures compliance with this specification
- Test cases cover both generation and parsing scenarios

## Migration Notes
- Previous vCard formats are supported for backward compatibility
- New contacts automatically use the standardized format
- Existing contacts are updated to new format when modified
